# NovaForge 产品升级计划 v1

**日期**：2026-11-20  
**范围**：烧录与串口稳定性 + 第三方开发板纳管 + AI 写固件体验 + 新手到烧录闭环 + 全端界面与性能  
**约束**：不破坏 Flash / Studio 双产品边界；不把 AI 带回小程序/weapp；二进制固件不承诺还原源码

---

## Context

用户选择了全部四个升级方向，并新增一条核心能力：连接任意 ESP32 系列开发板时，自动识别芯片、完整备份原固件、生成并烧录 NovaForge 官方固件。仓库已完成桌面双产品拆分、登录协议勾选、AI 仅保留在小程序之外等前置变更。本次升级在既有架构上扩展，不重写模块。

**安全前提**：二进制固件镜像无法可靠还原原始 C/Arduino 源码。可落地方案是「检测 → 备份 → 迁移可读配置（如有）→ 生成官方固件 → 确认 → 烧录 → 验证」，不承诺反编译。

---

## 阶段一：烧录与串口稳定性 + 第三方开发板纳管

### 目标
- 串口自动识别、状态可视化、失败诊断
- 第三方板接入 NovaForge 生态的完整安全流程

### 改动清单

1. **扩展 SerialManager 读写能力**（扩展现有 `src/renderer/src/lib/serial.ts`）
   - 新增 `readFlash(start, size)` 方法，调用 ESPLoader 的 `readFlash` 读取整段或分片
   - 新增 `readMac()`、`readChipInfo()` 轻量检测，在连接后立即返回芯片型号、Flash 大小、MAC
   - 复用 `pickPort()` + `ESPLoader.main()` 做"自动识别"，替代纯手动选串口

2. **DevicePage 增加「检测并纳管」向导**（`src/renderer/src/pages/DevicePage.tsx`）
   - 首屏三按钮：「选择串口」「自动检测」「打开监视」
   - 检测成功后展示卡片：芯片型号 / Flash 大小 / MAC / 是否 NovaForge 官方固件（通过读取分区表 Magic 字节判断）
   - 非官方固件时弹窗：
     - 步骤 1：**完整备份原固件** → 下载 `.bin` 到本地
     - 步骤 2：扫描备份中的可读配置（WiFi SSID / Home Assistant URL / 设备名）
     - 步骤 3：根据芯片自动选择 NovaForge 官方固件模板 → 调用 `buildFirmware()` 生成 → 自动编译
     - 步骤 4：预填迁移的配置到编译产物
     - 步骤 5：烧录（可擦除 + 写入）→ 烧录后验证（串口读状态命令 / 校验部分 Flash）
   - 复用 `shared/firmware.ts:buildFirmware()` 和 `shared/flash.ts:resolveFlashTargets()`，不新造轮子

3. **烧录可靠性增强**
   - `serial.ts`：烧录失败时记录原因分类（连接超时 / 固件不匹配 / 串口被占用 / 握手失败），返回结构化错误而非字符串
   - DevicePage 烧录进度改为「读取 bootloader → 擦除 → 写入分区表 → 写入 app → 重启 → 验证」七段进度条
   - 串口断开自动重试一次，重试仍失败提示用户手动复位开发板

### 新增文件
- `src/shared/serialBackup.ts` — 备份文件命名、分片拼接、校验和工具
- `src/renderer/src/components/BoardOnboarding.tsx` — 纳管向导 UI（DevicePage 内引用）

## 阶段二：AI 写固件体验

### 目标
让 AI 对话与固件编辑、编译、烧录形成闭环，Studio 专属，Flash 不触及任何 AI 接口

### 改动清单

1. **结构化编译错误传递**（`src/shared/types.ts` + `src/renderer/src/pages/Firmware.tsx`）
   - `BuildResult` 新增字段 `errors: Array<{severity: 'error'|'warning'|'info', file, line, col, message}>`
   - `Firmware.tsx` 编译失败时自动把最后 50 行 error 追加到 AI 对话上下文（AiChat 的系统提示里已有解释报错职责，直接喂数据）

2. **AI 回复 → Diff 预览 → 一键应用**
   - 新增 `src/renderer/src/components/DiffPreview.tsx`（Monaco 内置 diff editor 封装，两栏并排：左侧当前代码 / 右侧 AI 建议）
   - AiChat 消息渲染检测代码块（语言标记为 cpp/ino/python）时，右侧浮动「应用到编辑器」按钮
   - 点按钮：打开 DiffPreview → 用户确认后 patch 编辑器 → 自动触发编译
   - 编译成功 → 自动切换到 DevicePage 并预填烧录目标

3. **Studio/Flash 边界守护**
   - 所有 AI 相关组件在 `IS_FLASH` 时不挂载
   - `App.tsx` 路由守卫 + `gateway.ts` `/api/ai/*` 404 机制保持不变，不加新绕过

### 不做
- 不接入本地模型自动加载（Studio 用户自己配置）
- 不实现 Blockly 生成代码和 AI 的双向同步（Phase B2 考虑）

## 阶段三：新手闭环 + UX 统一 + 性能

### 目标
让新人从打开软件到跑通第一个设备不超过 5 步

### 改动清单

1. **首启向导 + 硬拦截改引导**（`src/renderer/src/App.tsx`）
   - 首启检测 localStorage 里没有 projectId 时，弹出四步向导：
     - Step 1：选择开发板（从 Workbench 现有板型列表里挑）
     - Step 2：创建项目（自动生成 hello-world 固件）
     - Step 3：连接串口
     - Step 4：编译 + 烧录
   - 向导完成后写入 localStorage，下次直接进工作台
   - 原 `firmware/device/control/ha` 页面的"还没选项目"硬拦截 → 改为显示向导入口卡片，不再阻断

2. **日志渲染节流**（`Firmware.tsx` + `DevicePage.tsx`）
   - `setLogs` 从"每次追加 slice(-500)"改为：缓冲区收集 → 每 100ms flush 一次 → 保留最新 500 条窗口
   - 自动滚动用 `requestAnimationFrame` 合并

3. **设计 Token 对齐**
   - 桌面 `src/renderer/src/styles.css` 提取 `--accent`/`--bg`/`--text`/`--radius`/`--font` 等共享 token
   - 移动/网页 `src/mobile/app.css` 和下载站 `site/assets/style.css` 同步同名变量（部分值适配移动端）
   - 不动小程序（weapp/uni-mobile 有独立设计，保持现状）

4. **状态记忆增强**
   - localStorage 额外存 `novaforge.lastProjectId` + `novaforge.lastBoardId` + `novaforge.lastPort`，首启自动恢复

### 不做
- 不重构 React 组件树或状态管理（保持 zustand store.tsx）
- 不动小程序/uni-app 的 UI 层（它们是独立项目）

## 验证计划

| 阶段 | 命令 | 通过标准 |
|------|------|----------|
| 类型 | `npm run typecheck` | 0 error |
| 桌面构建 | `$env:NODE_OPTIONS="--max-old-space-size=2048 --max-semi-space-size=8"; $env:RAYON_NUM_THREADS="2"; npm run build:studio` + 同上 `build:flash` | 两端均 exit 0 |
| 小程序 | `npm run build:mp-weixin`（uni-mobile） | Build complete，0 error |
| 真机烧录 | 接 ESP32-S3 / ESP8266 开发板 → Studio 设备页点"自动检测" → 备份 → 生成官方固件 → 烧录 | 七段进度走完，烧录后串口返回 NovaForge 状态命令 |
| AI 闭环 | Studio 固件页编译失败 → 打开 AI 面板 → 自动带错误 → 回复代码 → 点"应用" → 重新编译通过 | 无需手动复制粘贴 |
| Flash 边界 | Flash 构建 → 启动 → 侧边栏无 AI 入口 → 网关 AI 接口 404 | 无越界 |

## 实施顺序

```
Phase A1  串口读写封装 + 结构化错误          ← 底层，依赖最少
Phase A2  DevicePage 纳管向导 UI             ← 依赖 A1
Phase B1  编译错误结构化传递 + AiChat 挂钩    ← 独立，依赖 A1 可选
Phase B2  DiffPreview + 一键应用             ← 依赖 B1
Phase C1  首启向导 + 硬拦截改引导             ← 独立，可并行
Phase C2  日志节流 + Token 对齐 + 状态记忆    ← 独立，可并行
```

A1 → A2 必须串行；B1/B2、C1、C2 可以并行执行。
