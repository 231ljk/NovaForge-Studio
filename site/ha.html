烧好固件，剩下交给 Home Assistant

NovaForge 编译的 ESP32 固件内置局域网 HTTP 接口与 mDNS 广播。装好官方社区集成后，设备会被自动发现，引脚自动变成开关与传感器——不需要 MQTT Broker，也不需要刷 ESPHome、Tasmota。

查看安装步骤 集成仓库

三种接入方式

按网络环境选其一

官方推荐走社区集成：全局域网直连，不依赖任何中间服务。已经跑着 MQTT Broker 的环境可以直接用固件内置的 MQTT Discovery。前两者都不可用时，还有一份手动 YAML 兜底。

方式 通信路径 需要 MQTT 适用场景
社区集成推荐 mDNS 发现 + 局域网 HTTP 不需要 家庭局域网、无需额外服务
MQTT Discovery MQTT Broker 发布发现报文 需要 已有 Mosquitto / HAOS 环境
手动 YAML configuration.yaml 静态配置 需要 自动发现被网络隔离时的兜底

安装社区集成

两种装法，选一种

方式一：HACS 自定义仓库

推荐

仓库地址 https://github.com/231ljk/ha-novaforg，类别选 Integration。

1
打开 HACS 自定义仓库

HACS → 右上角菜单 → Custom repositories。

2
填入仓库地址

地址填上面的 URL，类别选 Integration，点击添加。

3
安装并重启

在 HACS 中安装 NovaForge，然后重启 Home Assistant。

方式二：手动复制目录

把集成目录整个放进 HA 配置目录，然后重启。

  • 将 custom_components/novaforge 复制到 Home Assistant 配置目录下的 config/custom_components/
  • 重启 Home Assistant，集成自动加载并开始监听局域网内的 NovaForge 设备

接入设备

从烧录到出现在 HA 里
1
编译并烧录固件

在 NovaForge Studio 中配置引脚功能，编译并烧录到 ESP32。烧录时固件会写入一枚 128 位随机控制令牌、以及由芯片 MAC 派生的硬件 ID。

2
设备联网并广播

设备连上 Wi-Fi 后通过 mDNS 广播 _novaforge._tcp 服务，TXT 记录中携带硬件 ID、设备名与固件版本。

3
在 HA 中确认发现

打开「设置 → 设备与服务」，会出现已发现的 NovaForge 设备，点击确认。

4
粘贴控制授权码

粘贴 NovaForge 软件「Home Assistant」页面显示的设备控制授权码，完成接入。也可以「添加集成 → NovaForge」手动输入设备 IP + 授权码。

输出引脚自动生成 开关（switch），输入引脚自动生成 二元传感器（binary_sensor）。

实体映射

引脚 → 实体
固件引脚 HA 实体 刷新方式 说明
输出引脚 switch 控制即时下发 开 / 关写入 1 / 0

MQTT 主题规范

使用 Discovery 时生效

固件内置 MQTT Discovery，联网后自动在 Home Assistant 注册实体。主题以 novaforge/<硬件ID> 为根，发现前缀固定为 homeassistant。

用途 主题
状态上报 novaforge/<硬件ID>/state/<引脚名>
控制下发 novaforge/<硬件ID>/set/<引脚名>
可用性 novaforge/<硬件ID>/available
发现报文 homeassistant/<switch|binary_sensor>/<硬件ID>/<引脚名>/config

发现报文示例

一个输出引脚（引脚名 relay）注册为开关时，发布到发现主题的内容：

{
  "name": "relay",
  "uniq_id": "nf-a4cf12ff7e2a-relay",
  "stat_t": "novaforge/nf-a4cf12ff7e2a/state/relay",
  "avty_t": "novaforge/nf-a4cf12ff7e2a/available",
  "dev": {
    "ids": ["nf-a4cf12ff7e2a"],
    "name": "客厅控制盒",
    "mf": "NovaForge",
    "mdl": "ESP32-DevKitC",
    "sw": "1.0.0"
  },
  "cmd_t": "novaforge/nf-a4cf12ff7e2a/set/relay",
  "pl_on": "1",
  "pl_off": "0"
}

开关的开关量约定为 pl_on = "1"、pl_off = "0"，与固件写入的值一致。

手动 YAML（兜底）

仅在自动发现不可用时使用，粘贴到 Home Assistant 的 configuration.yaml。Studio 可按当前工程直接生成这段内容。

mqtt:
  switch:
    - name: "客厅控制盒 - relay"
      unique_id: nf-a4cf12ff7e2a-relay
      state_topic: "novaforge/nf-a4cf12ff7e2a/state/relay"
      command_topic: "novaforge/nf-a4cf12ff7e2a/set/relay"
      payload_on: "1"
      payload_off: "0"
      availability_topic: "novaforge/nf-a4cf12ff7e2a/available"
  binary_sensor:
    - name: "客厅控制盒 - button"
      unique_id: nf-a4cf12ff7e2a-button
      state_topic: "novaforge/nf-a4cf12ff7e2a/state/button"
      payload_on: "1"
      payload_off: "0"
      availability_topic: "novaforge/nf-a4cf12ff7e2a/available"

控制权限与设备标识

为什么别人装了集成也控不了你的板子

控制必须持授权码

每个工程在烧录时写入一枚 128 位随机令牌。固件只接受携带令牌的 /api/set 请求——即使别人在自己家里装了这个集成、扫到了你的设备，没有授权码也无法操作任何引脚。

状态接口 /api/state 可匿名只读，方便做监控面板；写入一律校验令牌。

硬件 ID 不随改名变化

设备以芯片 MAC 派生的硬件 ID 作为唯一标识，形如 nf-a4cf12ff7e2a。多台设备同名、或之后随意修改设备名称，都不会串号、掉线或重复注册。

设备更换 IP 时，已配置条目的地址会自动更新。

全程局域网

社区集成方式下，状态轮询与控制请求都在本机局域网内完成（GET /api/state 十秒一次、GET /api/set 控制），设备数据不经过任何云端中转。

常见问题

接入过程中的高频疑问
需要刷 ESPHome 或 Tasmota 吗？

不需要。NovaForge 生成的固件本身内置局域网 HTTP 接口与 MQTT Discovery，直接用 Studio 编译烧录的固件即可接入。

没有 MQTT Broker 能不能用？

能。装社区集成后走 mDNS 发现 + 局域网 HTTP，全程不需要 MQTT。只有选择方式二（MQTT Discovery）时才需要 Broker，常见做法是在树莓派或 NAS 上跑 Mosquitto，端口 1883。

设备一直没被发现怎么办？

先确认设备与 Home Assistant 在同一网段，且路由器未开启 AP 隔离或屏蔽 mDNS。若网络确实隔离了组播，可以在 HA 中「添加集成 → NovaForge」手动输入设备 IP + 控制授权码，效果相同。

为什么确认发现时要填授权码？

授权码就是设备烧录时写入的控制令牌，用来证明你有权控制这台设备。没有它，任何人都能扫到并操作你的引脚。

输入引脚能不能反向控制？

不能。输入引脚注册为 binary_sensor，只读，按十秒周期轮询刷新状态；需要输出控制请使用输出引脚注册的 switch。

改了设备名字，HA 里会不会重复出现一台？

不会。实体与设备条目的唯一标识来自芯片 MAC 派生的硬件 ID，与设备名称、IP 都无关。
